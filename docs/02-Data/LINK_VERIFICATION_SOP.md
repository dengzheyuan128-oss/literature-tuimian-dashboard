# 链接质量检验标准操作流程 (SOP v2.0)

> **版本**: v2.0 (Dual-Notice & Multi-Channel Revision)
> **生效日期**: 2026-02-07
> **适用范围**: 钝学推免指南 - 130所院校推免通知链接质检
> **基于**: Kimi SOP 5.0（访问失败与多渠道验证版）适配

---

## 核心原则

> "数据准确性优先于来源形式，时效性优先于渠道正统性。夏令营与预推免同等重要，需分开收集。"

### 五大强制条款

1. **【双通知类型】** 每所院校需同时搜集夏令营和预推免两种通知（无则标注"未找到"）
2. **【时效性优先】** 2026届信息（2025年发布）优先，公众号时效性强可接受为A级
3. **【多渠道验证】** 官网失败时，立即启用搜索引擎精准定位（site:域名）
4. **【单校时限】** 每所院校处理时间≤5分钟，超时则标记待查
5. **【强制标注】** 所有链接必须标注来源渠道和通知类型

## 一、双通知类型说明

### 1.1 两种通知类型

| 类型 | 发布时间 | 关键词 | 说明 |
|------|---------|--------|------|
| **夏令营** | 5-7月 | 夏令营、优才夏令营、暑期学校 | 提前选拔，获得预录取资格 |
| **预推免** | 8-10月 | 推免、免试、接收推荐免试 | 正式推免接收 |

### 1.2 重要澄清

- **夏令营 ≠ 低质量链接**：夏令营是独立的招生渠道，与预推免同等重要
- **两者需分开搜集**：同一院校可能同时发布两种通知
- **部分院校只开其一**：如只有预推免无夏令营，则夏令营标注"未找到"

### 1.3 数据结构要求

每个program下的notices数组应包含：
```json
{
  "notices": [
    { "noticeType": "夏令营", "url": "...", ... },
    { "noticeType": "预推免", "url": "...", ... }
  ]
}
```

若某类型未找到：
```json
{ "noticeType": "夏令营", "url": "", "sourceChannel": "待查" }
```

## 二、高效搜索策略

### 2.1 核心理念：一次搜索，双重捕获

为避免反复搜索，采用"合并关键词"策略，一次搜索尽可能捕获两种通知类型。

### 2.2 搜索关键词模板

**Stage 1: 精准搜索（site限定）**
```
site:域名 2026 (推免 OR 夏令营)
site:chinese.pku.edu.cn 2026 (推免 OR 夏令营)
```

**Stage 2: 扩展搜索（无site限定）**
```
"北京大学中文系" 2026 (推免接收 OR 暑期夏令营)
"北京大学文学院" 2026届 免试研究生
```

**Stage 3: 分类搜索（仅当合并搜索无结果时）**
```
# 夏令营专项
site:域名 2026 夏令营 优才

# 预推免专项
site:域名 2026 推免 接收 免试
```

## 三、链接分级标准（A/B/C/D）

### 3.1 A级 - 具体通知页

**判定标准**（同时满足）：
- **时效性**：必须为2026届（2025年发布）
- **内容ID**：URL含 info/编码、c编码、node/、[a-f0-9]{16,} 等具体ID
- **类型明确**：明确标识为夏令营或预推免
- **内容完整**：含申请时间、要求、考核形式等关键信息

**来源扩展**（SOP 5.0新增）：
- **A级-官网原文**：*.edu.cn官方域名
- **A级-公众号原文**：mp.weixin.qq.com，时效性强可接受
- **A级-搜索引擎**：通过site:搜索发现的官方链接

### 3.2 B级 - 研究生院通知列表页

**判定标准**：
- 域名：yjsy.*.edu.cn / gs.*.edu.cn / graduate.*.edu.cn
- 内容：学校统一发布的推免总章或通知列表页
- 可从中找到具体推免通知

### 3.3 C级 - 院系列表页/模糊链接

**判定标准**：
- URL以/结尾或含list.htm特征
- 学院/系所主页
- 无法找到具体通知时的fallback

### 3.4 D级 - 第三方平台/无效链接

**必须清零**：
- 第三方聚合平台（lianpp.com、考研帮等）
- 404或无法访问
- 完全无关内容

## 四、访问失败处理SOP

### 4.1 失败类型判定

| 失败类型 | 处理方式 |
|---------|---------|
| HTTP 404/500 | 链接失效，搜索新链接 |
| Internal Error | 服务器防护，转搜索引擎策略 |
| 超时/无响应 | 重试1次后转搜索引擎策略 |
| 内容不匹配 | 跨校错位或类型错误，立即修正 |

### 4.2 三渠道策略

**渠道A：官网直接访问**
- 尝试访问现有链接
- 10秒超时限制

**渠道B：搜索引擎精准定位**
```
site:chinese.pku.edu.cn 2026 (推免 OR 夏令营)
```
- 找到则标注【渠道B-搜索引擎】

**渠道C：扩展搜索（无site限制）**
```
"北京大学中文系" 2026届 接收推免
```
- 公众号可接受，标注【渠道C-公众号原文】

### 4.3 放弃标准

三渠道均无结果时：
- 标记"待查"
- 记录建议联系方式（如有）
- **不攻坚**，单校≤5分钟

## 五、标准作业流程

### 5.1 单校处理流程（≤5分钟）

```
时间分配：
- Step 1-2: 官网访问尝试（30秒）
- Step 3: 合并关键词搜索（2分钟）
- Step 4: 扩展搜索（1.5分钟）
- Step 5: 结果记录（1分钟）
```

**详细步骤**：

| Step | 操作 | 时限 | 输出 |
|------|------|------|------|
| 1 | 访问现有夏令营链接 | 10s | 成功/失败 |
| 2 | 访问现有预推免链接 | 10s | 成功/失败 |
| 3 | 合并搜索 site:域名 2026 (推免 OR 夏令营) | 2min | 链接列表 |
| 4 | 扩展搜索（如需） | 1.5min | 链接列表 |
| 5 | 记录两种通知，标注来源渠道 | 1min | 数据更新 |

### 5.2 批量作业策略（每日20所）

**优先级队列**：
- **P0**: 已发现问题（访问失败、时效性错误）→ 立即处理
- **P1**: 985/211缺失通知类型 → 优先补全
- **P2**: 双一流/省属B级 → 快速升级
- **P3**: 四非D级 → 战略性放弃或标记待查

## 六、质量控制

### 6.1 每日Checklist

**【单校处理】**
- [ ] 尝试访问现有链接（10秒超时）
- [ ] 失败则启用合并关键词搜索
- [ ] 记录夏令营链接（或标注未找到）
- [ ] 记录预推免链接（或标注未找到）
- [ ] 核验时效性（必须为2026届）
- [ ] 标注来源渠道和通知类型
- [ ] 控制时间≤5分钟

**【批量作业】**
- [ ] 按P0→P1→P2→P3顺序处理
- [ ] 记录处理数量和成功率
- [ ] 生成当日报告

### 6.2 质量指标

| 指标 | 目标 | 说明 |
|------|------|------|
| D级链接 | 0 | 必须清零 |
| 985/211双通知覆盖率 | ≥80% | 同时有夏令营和预推免 |
| 整体A级占比 | ≥60% | A级链接占总数 |
| 来源标注完整率 | 100% | 所有链接都有sourceChannel |

### 6.3 月度复核

- **每月1日**：批量访问已核验A级，确认链接有效
- **每年5月**：夏令营季前全表复核
- **每年9月**：预推免季前全表复核

## 七、常见问题FAQ

### Q1: 夏令营和预推免有什么区别？

**夏令营**（5-7月）：
- 提前选拔优秀学生
- 获得预录取或加分资格
- 部分院校夏令营优秀者可直接录取

**预推免**（8-10月）：
- 正式推免接收
- 需要在推免系统中填报志愿
- 是最终录取环节

### Q2: 如果只找到一种通知怎么办？

正常情况。部分院校可能：
- 只开设夏令营（如部分985理工科院校中文系）
- 只开设预推免（如部分省属师范）
- 夏令营和预推免合并发布（标注为"综合"）

未找到的类型标注`"url": "", "sourceChannel": "待查"`

### Q3: 公众号链接可以认定为A级吗？

可以，在以下条件下：
- 时效性明确为2026届
- 内容完整（含申请时间、要求等）
- 标注【公众号原文】来源

SOP 5.0核心原则：**时效性优先于渠道正统性**

### Q4: 超过5分钟还没找到怎么办？

- 立即停止搜索
- 标记"待查"
- 记录已尝试的搜索方式
- 不攻坚，转处理下一所院校
