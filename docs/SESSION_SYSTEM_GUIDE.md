# 📘 会话记忆系统使用指南

> **版本**: v1.0
> **创建日期**: 2026-02-06
> **用途**: 帮助用户和Claude快速恢复会话上下文，避免重复交代背景

---

## 🎯 系统目标

解决以下痛点：
1. ❌ **每次启动Claude都要重新解释项目背景**
2. ❌ **不记得上次做到哪里了**
3. ❌ **不清楚当前项目健康状态**
4. ❌ **遇到的问题没有记录，下次又要重新排查**

通过4个核心文件，实现：
1. ✅ **2-3分钟快速上手** - QUICK_START.md
2. ✅ **1分钟恢复上次工作** - SESSION_CONTEXT.md
3. ✅ **30秒了解关键指标** - METRICS_DASHBOARD.md
4. ✅ **实时追踪阻塞问题** - BLOCKERS.md

---

## 📂 系统文件结构

```
docs/
├── QUICK_START.md           # P0 - Claude启动必读（2-3分钟）
├── SESSION_CONTEXT.md       # P0 - 会话上下文（1分钟）
├── METRICS_DASHBOARD.md     # P0 - 关键指标（30秒）
├── BLOCKERS.md              # P1 - 阻塞问题（按需）
└── SESSION_SYSTEM_GUIDE.md  # 本文件 - 使用指南
```

## 📖 各文件详解

### 1. QUICK_START.md（快速上手指南）

**用途**: Claude启动时的必读清单，包含项目核心信息和关键约束

**内容包括**:
- 项目核心信息（5秒速览）
- 当前状态和进度（30秒速览）
- 质量目标和停损线
- 禁止/允许的操作（关键约束）
- 关键路径和必读文档清单
- 关键决策速查（D-001至D-008）
- 数据结构速览
- 标准会话启动流程
- 常用命令速查

**适用场景**:
- ✅ Claude首次启动项目
- ✅ 长时间未接触项目（>1周）
- ✅ 新用户/协作者加入项目

**更新频率**: 项目状态变化时（如进入新PR、质量目标达成）

**阅读时间**: 2-3分钟（快速扫描）

---

### 2. SESSION_CONTEXT.md（会话上下文追踪）

**用途**: 记录每次会话的工作内容，确保下次启动能无缝接续

**内容包括**:
- 当前状态（一句话总结）
- 下次行动（优先级排序）
- 最近会话记录（做了什么、遇到什么问题、下次做什么）
- 重要发现与决策
- 当前工作区状态

**适用场景**:
- ✅ 每次会话开始时快速恢复上下文
- ✅ 每次会话结束时记录进展
- ✅ 中断工作后恢复思路

**更新频率**: 每次会话结束时更新（必须）

**阅读时间**: 1分钟

**更新模板**:
```markdown
### 会话 #X (YYYY-MM-DD - 会话主题)

**做了什么**:
- ✅ 完成任务1
- ✅ 完成任务2

**发现**:
- 发现1

**遇到的问题**:
- ❌ 问题描述

**本次会话成果**:
- ✅ 成果1

**下次应该做什么**:
1. 任务1
2. 任务2
```

---

### 3. METRICS_DASHBOARD.md（关键指标看板）

**用途**: 一眼了解项目健康度和进度，快速判断是否达到停损线

**内容包括**:
- 停损线目标（D级链接、健康度、第一梯队A级占比）
- 项目进度总览（PR完成进度、子任务进度）
- 链接质量分布（A/B/C/D）
- 梯队分布统计
- 数据完整性统计
- 关键问题追踪（D级链接、C级链接）
- 时间线追踪
- 成本追踪

**适用场景**:
- ✅ 快速了解项目健康状态
- ✅ 判断是否达到停损线
- ✅ 追踪PR进度
- ✅ 识别关键问题

**更新频率**: 完成PR或数据修复后更新

**阅读时间**: 30秒（快速扫描）

---

### 4. BLOCKERS.md（阻塞问题与技术债）

**用途**: 集中追踪当前阻塞问题、技术债和待决策事项

**内容包括**:
- 当前阻塞问题（P0 - 必须立即解决）
- 待决策事项（需要用户确认）
- 技术债（高/中/低优先级）
- 外部依赖与风险
- 已解决的问题（归档）

**适用场景**:
- ✅ 遇到阻塞问题时立即记录
- ✅ 识别技术债
- ✅ 追踪待决策事项
- ✅ 检查外部依赖状态

**更新频率**: 遇到问题时立即更新，解决后标记完成

**阅读时间**: 按需查阅

**问题追踪模板**:
```markdown
#### BLOCK-XXX: 问题标题
- **问题**: 详细描述
- **影响**: 影响的功能/任务
- **首次发现**: YYYY-MM-DD
- **优先级**: P0/P1/P2
- **尝试方案**: ...
- **状态**: 🔴 阻塞中 / ✅ 已解决
```

## 🚀 标准会话启动流程

### 对于Claude（AI助手）

#### 第1步：加载核心上下文（1-2分钟）

```markdown
新会话启动时，按优先级读取：

P0 (必读):
1. docs/QUICK_START.md       # 快速上手（首次启动或长时间未接触）
2. docs/SESSION_CONTEXT.md   # 恢复上次工作
3. docs/METRICS_DASHBOARD.md # 查看当前指标
4. docs/BLOCKERS.md          # 检查阻塞问题

P1 (按需读取):
5. docs/01-Project/PROJECT_STATUS.md   # 详细项目状态
6. docs/01-Project/DECISIONS.md        # 关键决策
7. docs/03-Plans/TODO.md               # 任务清单
```

#### 第2步：确认当前任务（30秒）

根据`SESSION_CONTEXT.md`的"下次行动"部分，确认本次会话要做什么。

#### 第3步：执行工作（主要时间）

- 按照`TODO.md`中的任务清单执行
- 遵守`QUICK_START.md`中的约束条件
- 遇到问题及时更新`BLOCKERS.md`

#### 第4步：会话结束前更新（2-3分钟）

```markdown
会话结束前必须更新：

1. SESSION_CONTEXT.md
   - 添加本次会话记录
   - 更新"下次行动"部分
   - 记录重要发现和遇到的问题

2. METRICS_DASHBOARD.md（如果完成了PR或修复了数据）
   - 更新进度条
   - 更新链接质量分布
   - 更新时间线

3. BLOCKERS.md（如果遇到新问题或解决了问题）
   - 添加新问题
   - 标记已解决问题
```

---

### 对于用户

#### 第1步：快速检查（30秒）

```markdown
每次会话结束后，快速浏览：

1. SESSION_CONTEXT.md - 确认Claude记录的内容准确
2. METRICS_DASHBOARD.md - 确认进度更新正确
```

#### 第2步：提出下次任务（可选）

如果有特定任务，在`SESSION_CONTEXT.md`的"下次行动"部分添加或修改。

#### 第3步：标记重要决策（按需）

如果做出了重要决策，考虑是否需要：
- 添加到`DECISIONS.md`（D-009, D-010...）
- 更新`PROJECT_STATUS.md`

## 🎨 最佳实践

### 1. 保持简洁
- 会话记录不要超过5条（超过后归档到99-Archive）
- 每条记录聚焦关键信息，不要过度详细

### 2. 使用状态标记
```markdown
✅ 已完成
🔄 进行中
⏳ 待开始
❌ 失败/阻塞
⚠️ 需要关注
```

### 3. 优先级分类
```markdown
P0 - 阻塞性问题，必须立即解决
P1 - 高优先级，影响当前工作
P2 - 中优先级，近期需要处理
P3 - 低优先级，可以延后
```

### 4. 定期维护
- **每周**: 检查`BLOCKERS.md`，清理已解决问题
- **每月**: 归档旧的会话记录到99-Archive
- **每PR**: 更新`METRICS_DASHBOARD.md`

## 🔧 故障排查

### 问题1: Claude没有读取会话文件
**症状**: Claude询问项目背景或重复问题
**解决**: 提醒Claude："请先读取docs/QUICK_START.md和SESSION_CONTEXT.md"

### 问题2: 会话记录过多难以查找
**症状**: SESSION_CONTEXT.md超过5个会话记录
**解决**: 将旧记录移动到`docs/99-Archive/session-history-YYYY-MM.md`

### 问题3: 指标不准确
**症状**: METRICS_DASHBOARD.md与实际数据不符
**解决**: 运行`pnpm check:data`重新统计，手动更新指标

### 问题4: 文档同步问题
**症状**: 不同文档中的信息冲突
**解决**:
- `QUICK_START.md`是简化版
- `PROJECT_STATUS.md`是详细版
- 以`PROJECT_STATUS.md`为准，同步更新`QUICK_START.md`
